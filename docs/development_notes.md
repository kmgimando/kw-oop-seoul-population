# 데이터 계층 개발 노트

## 초기 구현 범위

제안서의 데이터 객체·CSV 저장소 담당 범위부터 구현했다.
CSV 접근 책임은 `CsvPopulationRepository`, 한 기록의 검증·변환 책임은 `PopulationRecord`에 둔다.
탐지기는 파일을 직접 열지 않고 저장소에서 받은 객체 목록을 사용하도록 연결한다.

기존 탐지기와 맞추기 위해 `date`, `district_code`, `district_name`, `total_population`을 사용한다.
날짜는 문자열 대신 `datetime.date`로, 추정 인구는 소수를 유지하는 숫자로 저장한다.
서울시 합계와 각 자치구를 임의로 합산하지 않는다.

현재는 표준 라이브러리만 사용해 별도 설치 없이 실행할 수 있도록 했다.
AI를 활용해 초기 코드와 확인 항목의 초안을 작성했다. 본인 검토·수정과 후속 실험 결과는 아래에 추가한다.

## 현재 확인 대상

- 가상 CSV로 날짜 정렬, 자치구 선택, 시작일·종료일 포함 조회
- CP949로 저장된 CSV 읽기
- 잘못된 날짜, 음수·NaN·무한대 인구값, 필수 열 누락 거절
- 잘못된 행의 번호 표시와 재로딩 실패 시 기존 데이터 유지

초기 코드 확인 결과:

- `python -m unittest discover -s tests -v`: 7개 테스트 통과
- 가상 CSV 전체 조회와 2026-01-02~2026-01-03 기간 조회 실행 확인
- 제공된 실제 CP949 CSV: 35,126개 기록 로딩
- 지역 26개: 25개 자치구와 서울시 합계
- 기록 날짜 범위: 2023-01-01~2026-09-13
- 실제 탐지기 및 Flask와의 통합 실행은 아직 확인하지 않음

이 확인은 AI 도구 실행 환경에서 수행했다. 본인 PC의 실행·수정 결과는 아래에 추가한다.

## 다음 개발 순서

1. 실제 CSV를 실행해 지역 수·날짜 범위·조회 결과를 직접 확인한다.
2. 같은 자치구의 날짜 중복과 지역명 불일치, 누락 날짜를 검사한다.
3. 손호진 담당 `MigrationIndicators`의 생성 방식에 맞춰 유입·이동 열을 연결한다.
4. 권민우 담당 탐지기에 `PopulationRecord` 목록을 전달해 공통 형식을 검증한다.
5. Flask API에서 기준 계산용 과거 기록을 포함해 조회하고 화면 기간을 분리한다.
